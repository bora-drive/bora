# Bora v0.1.0 Close-out & GitHub Release — Design

Date: 2026-07-20. Approved by Andre in-session.

Closes out every remaining item in `TODO.md` and `docs/release-checklist.md`
and cuts a GitHub-only release (no PyPI). Two parallel tracks converge on the
release cut: Track A (on this VM) does code fixes, docs and release prep;
Track B (Andre) does the Cloud Console, second-account, Windows and Mac steps.

## Decisions taken

- `bora ls` shows native docs by their **projected leaf** (`live-doc.md`),
  matching disk and `path_display`.
- Repo **stays private** for this release. Update-check keeps failing cleanly
  and the Homebrew formula cannot be publicly installable yet; both documented.
- OAuth consent screen is **published to "In production" unverified** — this
  removes the 7-day refresh-token expiry. Full restricted-scope verification
  (privacy policy, demo video, CASA) is deferred to the public release.
- Homebrew formula is finalized **properly on Andre's Mac**
  (`brew update-python-resources`, `ruby -c`) against a tagged git URL.
- Release: tag `v0.1.0`, `gh release create` on the private repo with
  CHANGELOG notes and sdist+wheel attached. No PyPI. No repo-visibility flip.

## Track A — code fixes (TDD, offline tests, committed to main, no PRs)

1. **Export-toggle live reload.** The `export_google_docs` /
   `export_google_docs_markdown` setters in `main.py` (which execute inside
   the daemon when the CLI proxies to it) call
   `sync.reload_cached_config()` after writing config, so
   `bora export markdown off` takes effect without a daemon restart.
   An *unchanged* mirror still converts only on the Doc's next edit; with
   fix 2 landed, `bora rebuild-index` becomes a safe way to force
   conversion, and the CLI output says so.
2. **Rebuild-with-mirrors adoption.** In the download path, when a freshly
   exported `.bora-part` sidecar byte-matches the existing local file but the
   `download_only` index row is missing (post-rebuild / re-link), adopt the
   mirror silently: no conflict copy, no upload, re-seed the index row with
   the export hash. Closes the "mirror re-uploaded to Drive as a binary
   after rebuild" hole.
3. **`did_drop_table` follow-up.** Inspect the path-cache `Manager`; either
   wire the flag to a real consumer (a dropped path-cache table forcing a
   cursor/listing refresh) or delete the dead write — whichever the code
   supports — with a test.
4. **`bora ls` projected leaf.** Display native docs by the projected leaf
   derived from the canonical path. Regression test alongside the existing
   piped-`ls` test.

## Error handling / verification

- Every code fix lands test-first with offline regression tests.
- Fixes 1–2 get a live spot-check against the still-linked `smoke-test`
  config before tagging.
- Known orderings: mirror-adoption fix must land before any
  rebuild-based re-export advice ships; nothing is tagged until both tracks
  and the full suite are green.

## Out of scope

PyPI publishing, repo-visibility flip, full OAuth verification (CASA),
Shared Drives, webhook notifications, GUI.
